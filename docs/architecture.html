Architecture overview

Factory Inventory Management System

A two-tier demo app. A Vue 3 single-page app talks to a FastAPI backend over REST. There is no database: the backend loads seven JSON files into memory at startup and filters them in Python on every request.

System architecture

Three layers. Requests go left to right; data comes back right to left as JSON.

Tech stack

Few dependencies. Charts are hand-written SVG and there's no UI or state-management library.

Data flow: a filter change

What happens when a user picks a warehouse in the filter bar on the Dashboard.

  1. User changes a filter in FilterBar.vue

    It writes to the shared refs in useFilters.js. They're module-level singletons, so every view sees the same values.

  2. The view's watcher fires

    Dashboard.vue watches all four refs (period, location, category, status). It calls getCurrentFilters(), which maps location to warehouse and period to month.

  3. api.js builds the requests

    Filters set to "all" are left out. The Dashboard sends four requests in parallel: summary, orders, inventory, and backlog.

  4. FastAPI filters in memory

    apply_filters() does exact warehouse matching and case-insensitive category and status matching. filter_by_month() takes either 2025-03 or Q1-2025; quarters are expanded through QUARTER_MAP.

  5. Pydantic validates the response

    Endpoints that declare response_model are serialized against their model. Summary, spending, and report endpoints return plain dicts.

  6. Vue derives the display data

    The raw arrays go into refs. Computed properties work out KPIs, chart series, and currency formatting (USD, or JPY at a fixed rate of 150 when the locale is ja).

Things worth knowing

Gaps between the frontend and backend that I found while reading the code.

Frontend calls endpoints the backend doesn't have

  • App.vue loads tasks from /api/tasks, which returns 404. Errors are caught and logged, so the UI falls back to the hard-coded tasks in useAuth.js.
  • createPurchaseOrder posts to /api/purchase-orders. There's a CreatePurchaseOrderRequest model in main.py, but no route uses it.

Partially wired features

  • Backlog.vue exists but isn't registered in the router, so you can't navigate to it.
  • purchase_orders.json is empty, so has_purchase_order is always false.
  • Quarters are hard-coded to 2025 in QUARTER_MAP and the quarterly report.
  • The backlog count on the dashboard ignores the active filters.
